# FPL weekly app

React 19, TypeScript and Vite. Production is https://fpl-2026.vercel.app/;
Vercel's project root is `app`, and `master` is the production branch.

```sh
npm ci
npm run dev -- --host 127.0.0.1
npm test
npm run lint
npm run build
```

The local app is http://127.0.0.1:5173/. Vite forwards `/api/fpl?path=…` to FPL;
production uses `api/fpl.ts`. No FPL login or DeepSeek key is required in the
browser. `src/data/fpl.json` is generated by the root `export_app_data.py` and
must stay in step with `data/weekly.json` and the model's forecast identity.

## Weekly flow

- `ThisWeek.tsx` checks current account/forecast state before showing advice.
- `WeeklyBrief.tsx` presents transfers, captain/vice, starting team and deadline
  checks first, with a simple pitch and explicit bench order.
- `weeklyActions.ts` reads the selected action, calculates the displayed balance
  fallback and identifies lineup changes, including a vice-captain-only change.
- `coherence.ts` prevents old or mismatched data from becoming a current instruction.
- `DecisionReview.tsx` retains affordable alternatives, sourced observations and
  stress tests behind an optional disclosure.

The weekly backend publishes `decision.moves` and the lineup after those moves.
Never infer a sale from the diagnostic transfer tables or unconstrained future
path. A hold uses `plan.hold_weeks`; a transfer's resulting lineup must not show
the outgoing player. Public picks cannot confirm changes made since the last
deadline. Chip advice is shown only for a matching gameweek.

## Release checks

Run the app tests, lint and build, plus `.venv/bin/python -m pytest tests/ -q`
from the root. Verify the deployed page at desktop and phone sizes: instructions
appear after live data loads, the bench order fits, disclosures expand, and a
player opens the drawer. Check the console. A successful build alone does not
verify the live account or rendered page.
